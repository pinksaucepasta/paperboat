Windows Ctrl-C reaches the foreground program of a session shell (sanitized; winpool-2, GitHub-hosted Windows runner, test binaries built from 4810e5746 via cmd /c).
Cause (spark/ctrlc-flag-product.md): the host starts in its own process group (service_entry_windows.go), which marks it as ignoring Ctrl+C; every child inherits it (flag 1 on session-owner, cmd, powershell, ping). Fix: pty.Adapter.Start clears the flag before CreateProcess (ctrlc_windows.go).

TestNativeConPTYInterruptStopsAPingRunInPowerShell, host state emulated (ignore flag set before the adapter starts the shell):
  without the fix, 3 runs: FAIL FAIL FAIL (about 10.4 s each: timed out waiting for "Control-C", ping keeps replying)
  with the fix, 3 runs:    PASS PASS PASS (1.57 s, 1.57 s, 1.51 s; Interrupt true, Control-C printed, ping gone, shell alive)
