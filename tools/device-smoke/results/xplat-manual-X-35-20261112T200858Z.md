# X-35 first pass by hand on the shared fleet (lanex2), UTC 20261112 20:00-20:25 (IST 01:30-01:55 13 Nov)

Fleet builds: lanex2-l dev-64973afc6, apple (lanex2-m) dev-64973afc6, lanex2-w dev-85e45ee5c. Account: a throwaway console account of mine, not the fleet's account; on each machine an isolated profile (`pb --config <dir>/config.json`, XDG overlay, `auth.profile_dir`) so the fleet's own session was never touched. Approvals were made by a headless Chromium on Linux (the other machine of the three runs another OS for M and W).

## Part 1 PASS on L, M, W: `pb login --no-browser --json` prints the approval link, approving it signs the profile in
```
L: link printed, approved, `pb auth status --json` signed_in=true
M: link printed, approved, `pb auth status --json` signed_in=true
W: link printed, approved, `pb auth status --json` signed_in=true (the login process must stay alive: Windows OpenSSH kills a login started in a session that ends)
```
## Part 2 PASS on L, M, W: `pb switch personal` and `pb logout`, then status says signed out
```
switch personal -> "Switched active workspace to Personal. New commands use this scope; running operations are unchanged."   (L, M, W)
logout --json -> {"ok":true,"data":{"server_revocation":"complete","signed_out":true}}                                   (L, M, W)
auth status after logout -> signed_in=false                                                                               (L, M)
```
## Part 3 FAIL (logged): `pb switch` without a workspace, non-interactive, gives only "Paperboat could not finish the command" on L, M and W
```
pb: Paperboat could not finish the command. Check the current state before retrying; run `pb doctor` if this continues. Support reference: support_...
```
`pb switch --json` answers `unsupported_output`. In a script there is no message that says to pass `personal` or a team slug.
## Part 4 PASS on L, M, W: an API token is accepted by pb on each OS and one revocation ends it on all three
```
token minted once (console API), `pb login --api-token-file` on L, M, W -> signed in, `pb machine list --json` rc 0 on each
the token revoked once (DELETE api-tokens/<id>, HTTP 200)
`pb machine list --json` afterwards: L unauthenticated, M unauthenticated, W unauthenticated (Windows run with the token in a file; the
  harness's stdin pipe into pb.exe is not a product matter)
```
