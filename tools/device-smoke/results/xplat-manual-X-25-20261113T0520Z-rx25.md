Method: a throwaway pexpect driver (not committed) opens two interactive `pb connect` clients, each through the real OS of its client (L: ssh hp docker exec -it; M: ssh to the VM; W: ssh -tt to victus, ConPTY), like `xplat_term.py`. Starter A at 30x100 runs `pb connect <target> new --name "x25 sp ünï <combo><id>"`, joiner B (other OS, 40x120) runs `pb connect <target> --session "<same name>"`. Markers are computed by the shell (`echo M_x_$((6*7))`, `set /a`), size is read in the target (`stty size`, `[Console]::WindowHeight`). The PTY reports client rows minus one (pb's status bar row): 40x120 -> 39x120, 30x100 -> 29x100.
Replay checks render the joiner's raw byte stream through a VT emulator (pyte, alternate screen kept apart, LF as CRLF) and read text and colours.

## Found
- `pb connect <machine> new --name NAME` with a space, dot, non-ASCII or uppercase takes ~25 s on this build (names [a-z0-9] 3.6 s); a macOS client gives up with "pb: Operation canceled." at its 20 s dial budget in about one of five runs. Cause: the host's `session.ValidSessionName` still allowed only [a-z0-9_-] after 7f83cc386 relaxed server and CLI, so the server worker's create was refused and retried. Fixed in 0f92b3088 (TestValidSessionNameTakesTextAPersonTypes passes on CI run 43365789083); verify on the next cycle build.
