## 3. In-place `pb install` over an existing install on Windows
Reproduced in the Windows Sandbox on victus, cause found, no product defect: every install in a fresh guest started in the first ~5 minutes failed (7 attempts over 4 guests) with "installing runtime services / preparing the replacement executable" (startup-error log: `install supplied Windows runtime: Access is denied`; full message: `install Paperboat machine guard: read the local access domain from the Paperboat server; check the network and retry: ... GET /v1/client-configuration: ... Client.Timeout exceeded while awaiting headers`, windows-sandbox-first-install-error.txt). The elevated helper's one fetch of the local access domain (cli/internal/hostruntime/hostinstall/machine_guard.go:144) timed out on the guest's egress (victus path: ICMP fragmentation-needed from the first hop at 1472 bytes, windows-sandbox-network-probe.txt; curl from the same guest later took 0.6 s). Procmon (helper.exe) showed SHARING VIOLATION on Program Files directories and ACCESS DENIED on Write DAC of the half-installed runtime dir, i.e. the leftovers of the failed attempt, not a first cause (windows-sandbox-procmon-*.txt). The same builds failed the same way (87d7a5241, the predecessor's passing build; caf37d9c6; c6d670f93; 23aa30088), so it is not a regression. With the guest's network settled, install -> pair -> in-place install of the same exe over the paired install: install 30-63 s, doctor healthy, exec ok (windows-sandbox-guest-log-final.txt); the real PC (fleet lanex2-w, user pujan, dev-2eabcaecc -> dev-23aa30088 in place, 57 s) healthy and exec both ways (windows-fleet-in-place-install.txt). The guest script now retries install and pairs only after an install succeeded.
Side finding, not fixed: after a failed first install, `pb pair` fails with "An unfinished earlier enrollment ... run `pb reset` with this enrollment token file", and `pb reset --enrollment-token-file F` (as the same admin) printed nothing and did not clear it; the Sandbox was re-created instead.
