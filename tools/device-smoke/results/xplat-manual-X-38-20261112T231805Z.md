## Part 6 FAIL: system proxy is ignored and not named; explicit proxy failure is not named

Setup: macOS Ethernet (the only network service) had secure web proxy disabled and an auto-proxy URL (http://127.0.0.1:17391/proxy.pac, enabled). Recorded before the test and restored after (see cleanup).

6a. macOS network-settings proxy set to a closed port (`networksetup -setsecurewebproxy Ethernet 127.0.0.1 9`, state on), no HTTPS_PROXY anywhere:
```
pb doctor macx-l --json -> overall "degraded"; authentication pass, clock pass, daemon pass,
  hostd pass, peer_reachability pass, selected_path pass (direct)
```
The CLI and the daemon ignored the macOS proxy setting. The cause is the device build: AGENTS.md builds with CGO_ENABLED=0, and shared/httptransport/systemproxy_darwin_nocgo.go:1-12 (build tag `darwin && !cgo`) makes NativeSystemProxySource return an empty snapshot. `otool -L ~/.local/bin/pb` on M shows no SystemConfiguration link. Doctor does not name the ignored proxy at all. cli/docs/operations.md:219-222 says runtime traffic follows native macOS proxy settings, which is not true for this build. FAIL: not honoured, not named.

6b. HTTPS_PROXY set only in the user shell (`HTTPS_PROXY=http://127.0.0.1:9 pb doctor macx-l --json`):
```
rc=1; authentication fail "The Paperboat server did not accept the authenticated health check."
  recovery: "Check network access and sign in again if needed..."
clock warning "The Paperboat server could not be reached to read its clock."
peer_reachability fail "Could not establish an authenticated native connection to the selected machine."
```
Doctor does not name the proxy or HTTPS_PROXY. The proxy diagnosis only fires for typed ProxyError values (cli/cmd/pb/doctor_command.go:457 and 733-736); a refused connection to the proxy is a plain transport error, so the generic messages show.

6c. The daemon does not see the shell's HTTPS_PROXY: `HTTPS_PROXY=... pb status` still reports the daemon ready and macx-l ready. The LaunchAgent/LaunchDaemon plists (com.pinksaucepasta.paperboatd.plist and the paperboat.* LaunchDaemons) carry PAPERBOAT_* keys only and no HTTPS_PROXY, so the daemon's environment has no proxy. Doctor does not say that the daemon ignores the shell variable. FAIL.

6d. Administrator policy PAPERBOAT_HTTPS_PROXY: not tested (setting it needs a daemon restart, outside the brief's 30 s limit on the shared fleet).

Autoproxy: the pre-existing auto-proxy URL (proxy.pac on 127.0.0.1:17391, not listening) was not used by pb; doctor did not name it either.

## Findings for the lead
1. Native macOS proxy setting is ignored by device builds (CGO_ENABLED=0 selects shared/httptransport/systemproxy_darwin_nocgo.go, which returns an empty proxy). Either build the macOS CLI with cgo or correct cli/docs/operations.md:219-222. The lead decides which.
2. `pb doctor` does not name a dead explicit proxy (HTTPS_PROXY to a closed port): cli/cmd/pb/doctor_command.go:457 handles only typed ProxyError values.
3. path_display.py:45-46 (and the same helper used by dead_path_stream.py) leaves an orphaned `sleep 600` root process per UDP-drop run because failsafe.terminate() only kills the sudo wrapper; a fix is to kill the process group (start_new_session=True is already set).
4. Detached root failsafe for the firewall test did not survive its ssh session; the restore was by hand. Use launchd or a root-owned at job for failsafes on the Mac.
