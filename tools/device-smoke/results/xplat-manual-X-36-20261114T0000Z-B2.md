## Update of one machine mid-session keeps the other machine's sessions (xplat_midupdate.py TARGET CLIENT CANDIDATE_DIR)
Client holds a terminal (`pb connect`, a shell variable), a `pb ssh` into the target, a running exec and a 150 MB `pb send` to the target; the target serves a public tunnel.
Update 1 (`pb update --from <other build>`, no --force) while the ssh is open: refused `update_busy` "Paperboat is busy: N open SSH connection(s). Wait, close them, or use --force.", ssh stays alive, version unchanged.
Update 2 after the ssh is closed: succeeds; then the same shell answers with its variable, the exec returns, the transfer ends rc 0 with equal bytes, the tunnel answers 200 on the same URL.
```
target M (client L, dev-4eb842880 -> dev-982827507): PASS all (mid-M-pass)
target L (client W, dev-982827507 -> dev-4eb842880): PASS all
target W (client L, dev-982827507 -> dev-4eb842880): PASS all (a Windows sshd keeps the session until the remote command ends, so update 2 waited ~3 min for the count to drop)
