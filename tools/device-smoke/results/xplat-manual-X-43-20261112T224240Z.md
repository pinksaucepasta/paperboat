## Part 5 PASS for refusal (same result on all three hosts); defect in the error text
Raw requests to the viewer's local API socket (`POST /v1/inspector-requests`), targeting a preview on the host, with an empty grant and with an invalid grant. Viewer L socket `/run/user/1000/paperboat/local-api.sock`, viewer M socket `~/Library/Application Support/Paperboat/state/run/local-api.sock`.
```
L -> host M  (preview P):      no grant  -> 400 invalid_inspector_request (refused by the local API, nothing forwarded)
                               invalid   -> 503 inspector_unavailable "inspector request failed; check target connectivity with pb doctor"
M -> host L  (preview b158):   no grant  -> 400 invalid_inspector_request
                               invalid   -> 503 inspector_unavailable
L -> host W  (preview c12e):   no grant  -> 400 invalid_inspector_request
                               invalid   -> 503 inspector_unavailable
M -> host W  (preview c12e):   no grant  -> 400 invalid_inspector_request
                               invalid   -> 503 inspector_unavailable
```
The refusal is identical on M, L and W. Defect: a bad grant is reported as a connectivity failure (503), not an authorization error. Cause: the host-side authorizer rejects the grant while the native stream is set up (cli/internal/hostruntime/runtime/native_inspector_unix.go:37-45 returns the control-plane denial as a stream error), and the local API maps any untyped error to 503 `inspector_unavailable` (cli/internal/localapi/server_unix.go:570-571). Fix: return a typed denial from the host side and map it to 401/403 `inspector_unauthorized` there.
W as a viewer was not run (its local API is a Windows named pipe; the hosts are what the row asks for).
