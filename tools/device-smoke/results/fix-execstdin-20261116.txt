FIX-EXECSTDIN: pb exec stdin uses stdout's adaptive zstd and frames up to the 256 KiB limit (2026-11-16 IST)
Builds: before dev-ce199c78d (main), after dev-bd6620efe (the fix), installed with `pb install` on every machine.
Machines: L = two throwaway Linux containers on hp (xstd-ha caller, xstd-hb target, one account), W = GitHub Windows
runner winpool-13 (xstd-w-2), M = GitHub macOS runner macpool-3 (xstd-m). Relay = UDP blocked in the hp containers
(iptables in the container netns), pb ping path=regional_relay; direct = pb ping path=direct.
Data: rnd = /dev/urandom, txt = repeated log line (compressible). MB/s of `pb exec` wall time; stdin = `sh -c 'cat >/dev/null'`
fed from a file, stdout = `cat <file>` on the target. hp is on Wi-Fi and loaded: single runs vary a lot, so every
L cell is 2-4 runs. stdout is the unchanged path (control for link noise).

Byte-exact: sha256 of stdin as received by the target equals the source for rnd and txt, L->L (30 MB), L->W, W->L, M->L (8 MB).
M runs: the Mac caller against xstd-hb (on the after build; a before caller still sends 32 KiB raw frames).

Windows -> Linux follow-up (2026-11-16, winpool-5 xstd-w5 -> hp container xstd-hb, 8 MB, counters: Windows `netstat -s`
UDP datagrams sent + Get-NetAdapterStatistics, Linux iptables UDP counters in the container netns):
- pipe stdin from Windows: before (dev-bd6620efe) txt 1.15 MB/s in 885 datagrams, rnd 0.43; after the pipe fix
  (dev-d6a841f62) txt 3.03 MB/s in 94 datagrams (file redirect: 2.73 MB/s, 81 datagrams). The Windows pipe handed over
  <= 8 KiB per read, so frames were tiny; TestExecPipeInputFillsFramesFromASmallPipe fails on the old reader (8192
  bytes) and passes 20/20 on the fix (run on winpool-5).
- random stdin 0.06-0.31 MB/s vs stdout ~2 MB/s is the PATH, not exec or the Windows stack: on the direct UDP path
  Windows -> hp loses 16-61% of datagrams (e.g. 9205 sent, 4380 reached the container; NIC discards 0, errors 0),
  and stdout's ACKs from Windows are lost the same way (61%); when the session runs over the relay, random stdin is
  2.05-2.08 MB/s = stdout 2.07-2.78 MB/s with 0 QUIC loss. Open transport item: a direct path that loses half its
  packets is still used instead of a clean relay.
