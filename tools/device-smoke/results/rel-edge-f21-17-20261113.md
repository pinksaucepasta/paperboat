## Bug found
Before the fix (same drill, edge-1 -> control cut 90 s): public tunnel 200 for ~44 s, then 502 "durable data-carrier route is
unavailable" until control returned. Cause: the machine's attachment fetch to the server still worked; the server stops
listing an edge whose heartbeat is 30 s stale (server/internal/edgeplacement/placement.go:30), and the machine closed that
edge's healthy carrier as unwanted (cli/internal/hostruntime/runtimeattachment/service.go, machine diagnostic log
"carrier unwanted", reason pool_shutdown at +41 s). Fix: carrierRetired keeps a ready carrier the server stopped listing while
the pair has room (max 2). Test: TestUnlistedReadyCarrierStaysUpWhilePairHasRoom.
