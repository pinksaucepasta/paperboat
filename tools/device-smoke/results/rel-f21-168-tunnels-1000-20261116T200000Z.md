## Bugs found and fixed on the way (each with a test)
1. 612 of 1,000 reachable, then 0: the edge's ingress pull admitted its routes one transaction at a time (13 statements per route, 10 s for 1,000) and 10 s ingress decisions expired before use. `accountingauthority.RecordMany` admits a node's routes in one transaction per node (1ca3a992f; PG test `server/internal/billing/record_many_test.go`).
2. 0 reachable with 1,000 tunnels: the edge's route snapshot is the whole set of ONE EDGE NODE across all accounts (not per account), about 1.1 MB for 1,000 tunnels, over the edge's 1 MiB control-document limit, so it was thrown away whole. It is now paged (256 routes per page, cursor, one version for all pages, at most the node's 4,096 routes), not raised (63f73666a; `TestHTTPClientReadsARouteSnapshotPageByPage`, `TestHTTPClientRefusesARouteSnapshotThatChangedBetweenPages`, `TestRouteSnapshotPagesCoverTheSnapshotOnceInOrder`).
3. Route observations: 1,000 in one request took over 5 s (the edge's control timeout) and rolled back every time, so no route was ever ready. The edge reports 100 per request (63f73666a; `TestHTTPClientReportsRouteObservationsInBatches`).
4. Tunnel create reconciled and synced every tunnel of its machine (O(N)); it now takes the same incremental reconcile as preview create, one engine (140e26609; PG test in runtimeattachment/tunnel_endpoints_postgres_test.go).
5. The daemon's owner-session cap (1,024) was reported as "the service is restarting"; it is now typed `preview_session_limit_reached` and named (3e424df64; `TestPreviewSessionLimitIsTypedAndNamed`).
