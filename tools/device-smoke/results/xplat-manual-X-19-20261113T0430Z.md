## What the FAIL lines are
`https://<machine>.<domain>:<port>` for a port BELOW 1024 is not served by design (cli/internal/daemoncmd/coordinator_browser.go browserListenerPorts skips ports < 1024 except 80/443; cli/docs/cli.md:118). The same service is reachable through `pb access machine` (listen forms above), the private address, and `https://720.<machine>.<domain>` on every pair. The same URL form on the high port passes on every pair.

## Parts NOT passed, see failures.md
- DNS-rebinding filter: with dnsmasq 2.91 `--stop-dns-rebind` as the resolver (pbvm2, `dig @127.0.0.1 -p 5353 lanex2-m.ppr.boats`) the answer is EMPTY ("possible DNS-rebind attack detected"); the product has no fallback (PLAN 3b N4 lists it open). Public DoH resolvers answer 127.100.0.1 (cloudflare-dns.com and dns.google, curl dns-json), so a DoH browser resolves; no real browser was run on a fleet machine.
- VPN: not tested (the Mac VM carries Tailscale split-DNS files for ts.net only; names resolved there, which is not a full-tunnel VPN).
- Grant revoke (team grant / team setting ending a held private-access flow across OS): needs the two-account paid-team fixture of X-21; F9-04 (private_access_permission.py) does it Linux-only. Not run.
- Not run: per-OS trust-store inspection (Windows certificate store, macOS keychain, NSS) beyond curl through each OS's own store; `pb config local-access` alias/domain/proxy per client.
