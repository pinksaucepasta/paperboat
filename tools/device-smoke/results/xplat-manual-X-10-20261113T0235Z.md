Fixture (hp, removed afterwards): own sshd on a high port with its own host and client key (hp's authorized_keys untouched), an HTTPS git server with a throwaway private CA, bare repos for SSH and HTTPS, plus a local bare repo created per machine at its own native path.
L reaches hp over the container bridge; W and M reach it through `ssh -R` forwards, so their `[pull] url` / `[push] url` are aliases (127.0.0.1:<forwarded port>) for the same registered repository (registered once with L's URL). Each machine got its own credential profile with native absolute `ssh_key_file`, `known_hosts_file` and `ca_file`.
Parts, per machine: SSH profile saved + `pb config sync validate` ok; HTTPS + `ca_file` profile saved + validate ok; HTTPS without `ca_file` refused (not silently accepted); stored profile files 0600 (L, M) / protected ACL with only SYSTEM, Administrators and the user (W); token/key never in `pb config repository list|show|status` or validate output; own local bare repo validates on its own machine. Then every directed pair: a repository registered with machine A's local path, validated on machine B -> "This machine cannot reach the config repository" (rc 1, path not echoed). Six directions: L<-W, L<-M, W<-L, W<-M, M<-L, M<-W.
Only the first L local-bare validate attempt failed, because the container has no git so the repo was never created; it was recreated on hp and copied in, then passed (listed below). Scratch repos, credential files and sync file edits were removed/restored.
