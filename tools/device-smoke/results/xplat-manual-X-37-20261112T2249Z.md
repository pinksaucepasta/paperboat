### 2d. "Waiting for a direct connection or your relay": reproduced on the live M to L send
Reproduced in 2b, without any firewall change: the receiver path changed (direct, then none, then hosted relay) during the Unlimited send, and the sender printed the waiting text four times while it held the transfer and resumed each time. Code path read:
- cli/internal/localdaemon/file_transfer.go: `eligiblePath` allows only `PathDirect` and `PathSelfHostedRelay`; `openEligibleStream` returns `NoEligiblePathError` for any other kind, and wakes the peer first when the path is none.
- cli/internal/localapi/relay_quota.go: `NoEligiblePathError.Error()` returns "Waiting for a direct connection or your relay: only a Paperboat relay reaches this machine now" when the path is a hosted relay, and "...: this machine is not reachable now" otherwise.
- cli/internal/filetransfer/native_grant.go (`waitingForPath`, about line 280): the sender treats that refusal as a wait, not a failure, and resumes from the committed offset.
So the message appears exactly when an Unlimited stream finds only a hosted relay or no path. Reproduction left open: a receiver daemon stop for at most 30 s, during an Unlimited send, would produce the none branch; not run in this pass.
