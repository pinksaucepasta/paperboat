# FIX-V6ONLY: IPv6-only (NAT64+DNS64) machine starts connections through hosted endpoints given as DNS names

2026-11-13 20:15-20:45 IST, anvit (arm64 docker). Staging control plane pb-release-staging (edge and relay already registered with a DNS name, A record only, anvit has no global IPv6).

Setup (own, removed afterwards): docker bridge `v6o` fd39:39::/64, NAT64 tayga 64:ff9b::/96 + DNS64 unbound on the host; containers `v6o-l` (new build) and `v6o-lo` (old build) with every IPv4 address and route removed (`ip -4 addr` shows only 127.0.0.1, resolv.conf = the DNS64 resolver); `v6o-p` dual-stack peer. All paired into the staging account with `pb install` + `pb pair`.
Builds: new `pb version` dev-72c817bfc (this fix); old dev-d023709c9 (main, before the fix).

## Cause (code)
- Producers and verifiers already accept names: server/internal/runtimeattachment/service.go:275, controlplane/edge.go (`ValidateCarrierServerCertificateChain` uses `VerifyHostname`, IP or DNS SAN), edge deployment `connector_advertise_host`, pbh `--endpoint-host` (IP or DNS name), relay `RegionalNode.EndpointHost`.
- Client: TCP dials (h2 carrier, WSS relay) use Go's resolver and work for names. Both QUIC dials (`quic.DialAddr`: edge carrier, HTTP/3 transport, relay derpquic) bind an IPv4 socket and resolve with `net.ResolveUDPAddr`, which returns the A record whenever one exists: the DNS64-synthesized AAAA is never used. Fixed by shared/quicdial.
