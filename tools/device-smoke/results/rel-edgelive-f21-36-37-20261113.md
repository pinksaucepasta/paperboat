## Bugs found and fixed (commit 33e2f882a; staging ran the server image built from its first version 6ca6b6982, same server code, only tests and the CLI request validation differ)

   the command": cli/cmd/pb/tunnel_route.go required a stable_endpoint (empty there) and returned a plain error that the CLI maps to
   operation_failed/local_io. Now a TLS route is sent like a TCP one and the server names the managed host.
2. A TLS route with a verified domain was refused by the edge every 5 s (`assignment epa_route_... excluded: route is invalid`, the
   tunnel stayed connector_pending): the route snapshot (server control_plane.sql, engine_scoped_domain) rewrote it to the customer name
   with match_type exact; the edge accepts a TLS assignment only managed_exact (edge/internal/runtime/workers.go:1590) and takes the
   SNI from domain_bindings. Found by fetching the node's /v1/edge/routes/desired-state. The rewrite is now HTTP-only. After
   deploying it to staging the same route became ready and the check above passed.
