## Product bugs found and fixed
1. `pb config status` printed only "rx41n-l: conflict, bidirectional, manifest healthy" for a machine enrolled again whose old settings.json differs from the repository (pb doctor and pb status say nothing either; only `pb config conflict list` named the file). Fixed in 0b5b75495 (TestConfigStatusNamesConflictsAndHowToResolve, cli CI run 43528743741 with the PASS line): each conflict line names the file, the reason and the `pb config conflict compare` / `resolve --keep machine|repository` commands. Device check (dev-ccb2522a2, a forced concurrent edit on L and M): `conflict cfg/settings.json: merge conflict; see both versions with ... compare rx41n-l cfg/settings.json, then keep one with ... resolve rx41n-l cfg/settings.json --keep machine or --keep repository` (xplat-removal-config-conflict-status-20261116.out).
2. `pb reset` on Windows right after a revoke failed with "Windows installation failed while committing runtime state" (the machine was enrolled anyway): the startup-error log held the cause, `atomic file write failed: Access is denied` from MoveFileEx while another process held the destination for a moment. Fixed in bb1acce15: atomicfile.Write retries the replace for 5 s on access denied / sharing / lock violation (TestWindowsAtomicReplacementWaitsForABriefReader, Windows run 43787372125: PASS 0.40 s; the held-longer test still fails with its cause after 5.03 s). Device: revoke + reset of rx41n-w on dev-bb1acce15 (names flow) PASS.
