Fleet build dev-6c7e29534 (lanex2-l Linux container on hp, lanex2-m macOS hosted runner, lanex2-w Windows hosted runner). One line per part.

## Part 1 PASS: `pb ping` states the path (text and the same fields in --json)
```
lanex2-l -> lanex2-m: 4 x path=direct      lanex2-l -> lanex2-w: 4 x path=direct
lanex2-m -> lanex2-l: 4 x path=regional_relay  lanex2-m -> lanex2-w: 4 x path=direct
lanex2-w -> lanex2-l: 4 x path=direct      lanex2-w -> lanex2-m: 4 x path=direct
```
(the M->L pair is relayed while L->M is direct: the machines are behind different NATs and the Mac's direct attempt to the container does not succeed)

## Part 2 PASS: UDP blocked forces the relay, in both directions, and the path returns when the block is removed
UDP blocked on lanex2-l (iptables OUTPUT and INPUT drop, DNS port 53 left open): L->M, L->W, M->L, W->L all 4 x path=regional_relay.
UDP blocked on lanex2-w (Windows Firewall inbound and outbound block rules for UDP except 53, rules removed afterwards): M->W, L->W, W->L, W->M all 4 x path=regional_relay.
After the rules were removed: L->M 4 x direct; L->W 3 x direct and 1 x regional_relay in the first samples (path recovers within the first pings).

## Part 3 PASS: host firewall in its default state, no prompt left waiting
Windows: Defender Firewall enabled on Domain, Private and Public profiles with no Paperboat rule; the direct paths above worked without a prompt. macOS: application firewall is off (the macOS default). Linux: no ufw or firewalld in the container, iptables ACCEPT. No dialog or prompt was left waiting on any machine (the runs are non-interactive and every command returned).

## Part 4 PASS: the system proxy is honoured
A local HTTP CONNECT proxy on each machine and HTTPS_PROXY=http://127.0.0.1:28080 for `pb doctor`: doctor healthy on L, M and W and the proxy saw one CONNECT to the API host on each. With a dead proxy (127.0.0.1:9) doctor fails authentication/clock checks ("The Paperboat server did not accept the authenticated health check", "could not be reached to read its clock"); it does not name the proxy in this case.
Not done: the daemon's own proxy variables (PAPERBOAT_HTTPS_PROXY for the managed service), macOS network settings and Windows WinHTTP/WinINET settings, because they need a service-level configuration on the shared fleet.
