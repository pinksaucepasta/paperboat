# Status page drill, 2026-11-18 (staging: the anvit admin stack, never prod)

Stack: pb-admin-stg-server, -edge and -relay (systemd user units on the staging host). Two vantage points (oracle, anvit) probe the stack every
minute and post to a local copy of the status API (`dev/wrangler.staging.jsonc`, the same `lib/` code that runs in Pages Functions and the cron
Worker). `drill.py` stops one service at a time from a fully green page, waits for its component to turn red (major), starts it, waits for green.
The staging catalog has one unit per component (an API health + read pair, one relay, one edge), so a stopped service means every unit of that
component fails.

| Component | Service stopped | Red after (s) | Green after start (s) | Other components moved | Result |
|---|---|---|---|---|---|
| relays | pb-admin-stg-relay | 171 | 301 | none | PASS |
| edges | pb-admin-stg-edge | 176 | 299 | none | PASS |
| api | pb-admin-stg-server | 161 | 301 | none | PASS |

Red needs three failing checks in a row from both vantage points (about 3 minutes at one check a minute, plus the cron minute); green needs five
passes in a row (about 5 minutes). No other component left operational in any run.

Runs: relay and edge in one run (the first row pair), the API in a second run. Earlier runs on 2026-11-18 were not valid and are not counted: the
first was cut off when files under the running local Worker were moved; the second stopped before the edge because the stack's own services were
restarted and rebuilt by other work on the same host, and the oracle-to-host path was unreachable for 3 minutes while the other vantage point still
passed (the page correctly showed degraded, never red, on that single witness); the first API attempt of the final series had the API service
restarted by someone else during the 3-minute window, so it never went red.
