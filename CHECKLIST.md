# Paperboat launch checklist

The **only** progress tracker. PLAN.md explains each item (decisions, scope, starting points);
this file records whether it works. Work top to bottom: finish Part A for a section, together
with that section's commands in Part B, before starting the next section.

## How to mark

- A cell is a platform: **L** = Linux (hp), **M** = macOS (apple), **W** = Windows (victus).
  `—` = not platform-specific (one result for the whole item, recorded in the L cell).
- `[ ]` not verified · `[~]` in progress · `[x]` verified on the real device · `[!]` fails
  (write the failure in Evidence) · `n/a` impossible on that platform (say why in Evidence).
- Mark `[x]` **only** with evidence in the Evidence column: a smoke-suite test id with the
  results file (`smoke:<id> results/<file>.json`), or the commit and exact command/output
  summary for a manual check (`manual: <commit> <what was run> → <result>`).
- When a fix changes code, re-verify every `[x]` row in the same section on all platforms;
  any row that breaks becomes `[!]` and is fixed before anything else (AGENTS.md: regressions first).
- Commit and push this file together with the work it records.

## Command verification standard (Part B)

Every command row is `[x]` on a platform only when, on that platform, all of these hold:
1. the main use works against real machines/server and its result is correct;
2. every flag shown in `cli/docs/cli/<command>.md` behaves as documented (or the doc is fixed);
3. `--json` output (where supported) is valid and stable;
4. errors are clear for: invalid input, missing permission, target offline, not signed in;
5. `--help` text is accurate;
6. it is covered by the smoke suite when it can be automated.
Commands marked `LEGACY?` must first be decided: if they are leftovers with no user value,
delete them (code, docs, tests) and strike the row with the commit; otherwise verify them.
